# 피처 알고리즘 조사와 설계

알고리즘 선택이 실제로 필요한 요구사항에만 적용한다. `intent.md`, 요구사항 원문, 인터뷰에서 채택된 요구를 반영한 `spec-design.md` 초안과 관련 질답을 함께 읽는다. 알고리즘의 입력·출력, 반드시 지킬 규칙, 입력 규모와 시간·메모리 제약을 먼저 정리한다. 선택에 필요한 조건이 빠졌다면 관련 역할에 다시 묻고 설계 초안을 갱신한 뒤 비교한다.

## 후보 찾기와 검토

- 알려진 유사 방법을 먼저 조사한다. 필요하면 `research` 스킬로 공식 문서·원논문·원본 구현 등 1차 출처를 확인한다. 사용할 수 없으면 직접 조사한다.
- 각 후보가 정답 조건을 지키는 이유와 깨지는 입력·경계 사례를 검토한다. 입력 규모에 비춰 시간·공간 비용과 전제 조건을 비교한다. 출처가 입증한 사실과 추정 성능을 구분한다.
- 적합한 기존 방법이 없을 때만 직접 설계한다. 기존 방법이 맞지 않는 이유, 새 방법의 처리 순서, 정답 조건을 지키는 근거와 반례 후보를 기록한다. 검증되지 않은 방법은 확정된 해법으로 제시하지 않는다.

## 개발자 선택

- 의미 있는 대안을 최대 3개만 [템플릿](../feature-workflow/assets/algorithm.md)에 정리한다. 비교표에는 후보당 한 줄로 핵심을 적고, 모든 후보의 방식·요구 적합성·한계를 짧게 설명한다. 복잡한 방법에만 작은 입력·출력 예시를 추가한다.
- 선택 전에는 추천과 그 이유를 `검토 중`으로 표시한다. 개발자에게 선택을 물어 답을 해당 질문 문서에 기록한 뒤 `선택됨`으로 바꾸고, 선택 이유·감수할 한계·검증 방법을 남긴다. `spec-design.md`에는 확정된 방법과 핵심 근거만 반영한다.

주 에이전트가 조사 결과를 검토하고 문서 및 설계에 반영한다. 별도 에이전트가 없어도 이 지침을 직접 따른다.
