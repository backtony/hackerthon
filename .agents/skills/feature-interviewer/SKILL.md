# 피처 인터뷰어

담당자가 아는 사실을 발견하는 인터뷰다. 사용자가 질문을 담당자에게 전달하고 답을 가져오며, 주 에이전트가 대화와 문서를 관리한다. 별도 에이전트가 없어도 같은 방식으로 진행한다.

## 질문 준비

- `intent.md`, 요구사항 원문, `spec-design.md` 초안, 대상 역할과 앞선 질답을 읽는다. 먼저 그 역할만 답할 수 있는 정보와 설계에 영향을 줄 정보의 빈틈을 찾는다. 파일·코드에서 확인할 수 있는 사실은 직접 확인한다.
- 명시된 기능의 실제 사용 흐름뿐 아니라 불편, 예외, 운영 규칙, 기대하지만 적히지 않은 기능, 구현에 영향을 주는 제약도 탐색한다. 새 기능 제안은 확정 요구사항과 구분한다.
- 우선순위가 가장 높은 **질문 하나**를 대상 역할과 함께 제시한다. 담당자가 원래 대화를 몰라도 답할 수 있도록 필요한 맥락을 질문 안에 짧게 넣고, 그대로 복사할 수 있게 쓴다. 한 질문에는 한 가지를 묻고, 답을 유도하는 권고안은 붙이지 않는다. 제시하기 전에 실제 질문을 `question-<role>.md`에 `답변 대기`로 기록한다. 재개 시 대기 중인 질문이 있으면 새 질문보다 먼저 이어간다.

## 답변을 받은 뒤

- `question-<role>.md`의 해당 질문에 의미 있는 답변 원문, 확인된 사실과 새 요구 제안을 구분해 기록하고 `답변 대기`를 해제한다. 답변이 모호하면 조건·적용 대상·예외를 후속 질문으로 확인하고, 답에 따라 다음 질문을 정한다. 답을 받기 전에는 다음 질문으로 넘어가지 않는다.
- 답을 모른다는 경우에는 미해결로 남기고 답할 수 있는 역할을 찾는다. 역할 간 답이 충돌하거나 새 요구의 채택 여부를 정해야 하면 결정권자에게 확인한다. 담당자의 희망만으로 `spec-design.md`에 확정 요구를 추가하지 않는다.
- 해당 역할의 설계에 영향을 주는 빈틈을 모두 확인했는지 살피고, 마지막에 빠뜨린 요구나 예외가 있는지 묻는다. 해결되지 않은 질문은 표시한 채 다음 역할로 넘기거나 결정권자의 범위 결정을 받는다.

`question-<role>.md`는 `역할 → 확인 요약 → 주제별 질답 → 미결 사항` 순서로 쓴다. 각 질답에는 실제 질문, 답변 원문, 확인된 사실 또는 새 요구 제안과 결정 상태를 구분해 둔다. 역할을 마치면 질답을 주제별로 묶고 인사말·중복만 줄인다. 조건·수치·권한·순서가 담긴 답변 표현은 보존한다. 다음 역할은 앞선 역할의 답을 참고한다. 최종 구현 기준은 승인된 `spec-design.md`다.
